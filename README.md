# Socio

Socio помогает вести учёт социальных услуг и готовить отчёты. В приложении можно увидеть услуги и клиентов в одной таблице, изменить количество посещений и выгрузить результат в Excel.

Для знакомства с проектом не нужен сервер: в репозитории есть демонстрационные данные и пример шаблона отчёта. Все имена, услуги и тарифы в демо вымышлены.

## Что умеет приложение

- Показывать услуги, клиентов и итоговые значения в одной таблице.
- Редактировать количество посещений и фильтровать услуги по названию.
- Отправлять изменения параллельно, с повторными попытками и проверкой результата.
- Выгружать отчёт в Excel с тарифами, формулами и оформлением шаблона.

Приложение написано на **React и TypeScript**. Для сборки используется Vite, для работы с Excel — ExcelJS, для тестирования — Vitest.

## Быстрый старт

Понадобятся Node.js **20.19+ или 22.12+** и npm.

```bash
npm ci
npm run dev
```

Откройте адрес из терминала — обычно это `http://localhost:5173`. Введите любой непустой логин и пароль: в деморежиме они не проверяются сервером. Попробуйте изменить значения в таблице и нажать «Экспорт в Excel».

Демо работает в памяти браузера: после перезагрузки страницы изменения сбрасываются. Подробнее о запуске — в [Quick Start](QUICKSTART.md).

## Шаблон Excel

Пример отчёта находится в `public/templates/report-template.demo.xlsx`. В нём десять вымышленных услуг с условными тарифами и нормативами. При экспорте приложение подставляет данные из таблицы, сохраняет оформление и формулы, добавляет недостающие столбцы клиентов и удаляет неиспользуемые строки услуг.

Для работы со своим шаблоном положите его в `public/templates/report-template.xlsx` и укажите в `.env.real.local`:

```dotenv
VITE_REPORT_TEMPLATE_PATH=templates/report-template.xlsx
```

Этот файл исключён из Git. Сопоставление названий услуг находится в `src/services/serviceNameMapping.ts`: правила в репозитории демонстрационные, поэтому для своей системы их потребуется настроить. Услуги без соответствия или с нулевыми значениями не попадут в отчёт. При изменении структуры книги проверьте экспорт тестами и вручную в Excel: расположение итогов и формул зависит от шаблона.

Файлы из `public/` копируются в сборку и становятся доступны пользователям сайта. Не публикуйте сборку с закрытым рабочим шаблоном.

## Подключение к серверу

В проекте есть интеграция с Oracle APEX. Для локального подключения скопируйте `.env.example` в `.env.real.local`, задайте адрес сервера в `API_PROXY_TARGET` и числовой ID приложения в `VITE_APEX_APP_ID`, затем выполните:

```bash
npm run prod
```

Команда запускает сервер разработки Vite с прокси. Для работы с реальным API нужны доступ к совместимому приложению Oracle APEX и учётная запись. Подключение и правила сопоставления услуг требуют проверки в конкретном окружении.

Локальные `.env`-файлы исключены из Git. Не храните секреты в переменных с префиксом `VITE_`: их значения, в том числе ID приложения, доступны в браузере. Адрес прокси `API_PROXY_TARGET` используется сервером разработки.

Для production-сборки с интеграцией используйте `npx vite build --mode real` после настройки `.env.real.local`. Собранное приложение обращается к `/api`; сервер публикации должен проксировать этот путь и корректно обрабатывать cookies и перенаправления. Прокси Vite в production-сборку не входит.
