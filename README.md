# Socio

Веб-приложение для подготовки отчётов об оказанных социальных услугах. Таблица связывает услуги и клиентов, позволяет редактировать количество посещений и выгружать отчёт в Excel. В репозитории используется обезличенный шаблон и демонстрационные данные.

## Возможности

- Таблица услуг и клиентов с итогами, закреплёнными столбцами и горизонтальной прокруткой.
- Редактирование посещений и параллельная отправка изменений с повторными попытками и проверкой результата.
- Экспорт `.xlsx` на основе шаблона: сопоставление услуг, тарифы, формулы, форматирование и дополнительные столбцы клиентов.
- Демонстрационный API для запуска без сервера и интеграция с Oracle APEX для настроенного окружения.

Стек: React, TypeScript, Vite, Vitest, ExcelJS и CSS.

## Запуск

Нужен Node.js 20.19+ или 22.12+ и npm. Подробнее — в [QUICKSTART.md](QUICKSTART.md).

```bash
npm ci
npm run dev
```

Откройте адрес, показанный Vite (обычно `http://localhost:5173`). Для входа в демо подойдут любые непустые логин и пароль. Данные демонстрационного API хранятся в памяти и сбрасываются после перезагрузки страницы.

```bash
npm test          # тесты
npm run build     # проверка TypeScript и production-сборка в dist/
npm run preview   # локальный просмотр сборки
```

Обычная production-сборка работает с демо API. Сборка с реальной интеграцией: `npx vite build --mode real` после настройки `.env.real.local`.

## Настройка интеграции

Скопируйте `.env.example` в `.env.real.local`, укажите адрес сервера в `API_PROXY_TARGET` и числовой ID приложения Oracle APEX в `VITE_APEX_APP_ID`, затем выполните `npm run prod`. Эта команда запускает **dev-сервер** Vite с прокси, а не production-сервер. Для реального API нужны доступ к совместимому Oracle APEX, учётная запись и соответствующая серверная настройка.

Все `.env`-файлы, кроме `.env.example`, исключены из Git. `API_PROXY_TARGET` читается конфигурацией Vite на стороне сервера разработки. Переменные с префиксом `VITE_`, включая ID приложения, включаются в браузерный код и доступны пользователям приложения. Не помещайте в них секреты, пароли и токены; учётные данные вводятся пользователем при входе.

В production приложение обращается к относительному пути `/api`. Настройте на сервере публикации reverse proxy для этого пути, включая cookies и перенаправления: прокси Vite в собранном приложении отсутствует. Адрес backend в настройках инфраструктуры должен оставаться приватным. Реальная интеграция зависит от конкретного приложения Oracle APEX и требует отдельной проверки в его окружении.

## Excel-отчёт

В репозиторий включён только демонстрационный `public/templates/report-template.demo.xlsx`: в нём 10 вымышленных услуг и условные значения. Для реальной работы поместите актуальную книгу в `public/templates/report-template.xlsx` и укажите `VITE_REPORT_TEMPLATE_PATH=templates/report-template.xlsx` в `.env.real.local`. Этот локальный файл исключён из Git. Названия услуг сопоставляются в `src/services/serviceNameMapping.ts`: публичные правила тоже демонстрационные и для реальных данных требуют собственной настройки. Услуги без соответствия и ненулевых значений не экспортируются. Не размещайте рабочую книгу в публичном хостинге: файлы из `public/` и собранной папки `dist/` доступны пользователям сайта.

Формулы и позиции итогов зависят от структуры книги. При изменении шаблона, включая строку 54, проверяйте экспорт тестами и вручную в Excel. Имена и показатели в демонстрации вымышлены; тарифы и правила сопоставления приведены для демонстрации и требуют проверки перед реальным использованием.

## Ограничения

Демо не сохраняет изменения между перезагрузками. Тесты не заменяют проверку с реальным Oracle APEX или проверку формул в Excel. Публикация frontend сама по себе не предоставляет backend и не настраивает авторизацию.
